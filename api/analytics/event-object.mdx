---
title: "The Event Object"
description: "Events represent user interactions with your content — views, engagement, playback quality, and ad lifecycle."
---

Events are created automatically by the SDK as users interact with your feed. Each event captures a specific interaction — a video impression, a like, a share, or detailed playback telemetry like rebuffering and quality changes.

You don't need to create events manually. The SDK batches and sends them to `POST /v1/events` using your publishable key. This reference documents the event shape and types so you can query and filter them via the API.

## The event object

```json
{
  "id": "e8f9a0b1-c2d3-4e5f-6a7b-8c9d0e1f2a3b",
  "event_type": "playStart",
  "content_id": "d290f1ee-6c54-4b01-90e6-d701748f0851",
  "user_id": "user_abc123",
  "session_id": "sess_xyz789",
  "view_session_id": "vs_a1b2c3d4",
  "timestamp": "2026-03-01T12:00:00+00:00",
  "received_at": "2026-03-01T12:00:01+00:00",
  "event_data": {}
}
```

---

## Attributes

<ResponseField name="id" type="string">
  Unique event identifier (UUID).
</ResponseField>

<ResponseField name="event_type" type="string">
  Event type. See the full list below.
</ResponseField>

<ResponseField name="content_id" type="string | null">
  Content ID this event relates to. Null for feed-level events like `feedEntry`.
</ResponseField>

<ResponseField name="user_id" type="string">
  User identifier. Defaults to `"anonymous"` if the SDK has no identity set.
</ResponseField>

<ResponseField name="session_id" type="string | null">
  Session identifier grouping events within a single app session. For inline surface events it is the surface session (see below).
</ResponseField>

<ResponseField name="view_session_id" type="string | null">
  View session identifier grouping all events for a single content view (from impression through exit).
</ResponseField>

<ResponseField name="timestamp" type="string">
  ISO 8601 timestamp of when the event occurred on the client.
</ResponseField>

<ResponseField name="received_at" type="string">
  ISO 8601 timestamp of when the server received the event.
</ResponseField>

<ResponseField name="event_data" type="object">
  Event-specific payload. Shape varies by event type.
</ResponseField>

## Event types

### Engagement

| Type | Description | Key `event_data` fields |
|------|-------------|-------------------|
| `impression` | Content entered the viewport | — |
| `playStart` | Video playback began | — |
| `watchProgress` | Periodic heartbeat during playback | `watchTimeMs`, `playingTimeMs` |
| `completion` | Video played to the end | `watchTimeMs` |
| `like` | User liked the content | — |
| `share` | User shared the content | `shareMethod` |
| `save` | User saved/bookmarked the content | — |
| `swipe` | User swiped to the next item | `direction` |
| `interaction` | Generic UI interaction | `action` |
| `live.viewer.heartbeat` | Live stream viewer presence ping. Sent by the SDK every 30 seconds while a live item is the active playing item. Drives the `currentViewers` count on live content. | `playbackId`, `viewerSessionId` |

### Playback quality

| Type | Description | Key `event_data` fields |
|------|-------------|-------------------|
| `firstFrame` | First video frame rendered | `startupTimeMs` |
| `rebuffer` | Playback stalled for buffering | `durationMs` |
| `qualityChange` | Adaptive bitrate switch | `fromBitrate`, `toBitrate` |
| `error` | Playback error | `errorCode`, `errorMessage` |

### Feed navigation

| Type | Description | Key `event_data` fields |
|------|-------------|-------------------|
| `feedEntry` | User entered the feed | `entryPoint` (`feed`; on Web also `presented` for a feed your page opened full screen; `widget`, `tileGroup` or `player` when opened from a surface, with `originSurfaceId`, `originSurfaceSessionId`, `originContentId` and `seedPath`) |
| `feedExit` | User left the feed | `videosWatched`, `totalSessionTime`, plus the same origin fields as the matching `feedEntry` |

### Inline surfaces

Widgets, tile groups, single players and the web miniplayer report their own engagement, separate from the feed. These events have no `view_session_id`: a muted preview is not a video view and does not count toward views or watch time. Their `session_id` is the surface session, one on-screen episode of that surface.

| Type | Description | Key `event_data` fields |
|------|-------------|-------------------|
| `inlineEntry` | The surface came on screen | `itemCount` |
| `inlineImpression` | An item was at least half visible for 500 ms, once per surface session and item | `position` |
| `inlinePreviewStart` | A muted preview showed its first frame | `position`, `startupMs`, `trigger` (`autoplay`, `rotation`, `pin`, `resume`) |
| `inlinePreviewEnd` | The preview stopped | `position`, `playedMs`, `loops`, `reason` (`rotated`, `scrolledOut`, `deactivated`, `tapped`, `released`, `background`, `hidden`) |
| `inlineTap` | The viewer tapped an item | `position`, `action` (`feed`, `fullscreen`, `mute`, `host` when your tap handler took it, `none`; `expand` or `dismiss` on the web miniplayer), `routed` (`true` when the SDK or your handler acted on the tap), `previewing`, `previewMs` |
| `inlineExit` | The surface left the screen | `dwellMs`, `impressions`, `previews`, `taps`, `reason` (`hidden`, `background`, `released`) |

Every inline event's `event_data` also carries:

| Field | Description |
|-------|-------------|
| `surface` | `widget`, `tileGroup`, `player` or `miniplayer` |
| `surfaceId` | Stable identifier of the surface instance |
| `surfaceSessionId` | The surface session; equals the event's `session_id` |
| `layout` | `carousel`, `grid`, `host`, `single` or `floating` |
| `playbackMode` | `rotating` (one preview at a time), `simultaneous` (all visible previews), `gridAlternating` or `none` |
| `source` | `algorithmic` (ShortKit chose the items) or `host` (your app supplied them) |

`dwellMs` counts the whole time the surface was on screen, including time under a feed it opened. The web miniplayer reports entry, impressions, taps and exit only.

Click-through for a surface is taps that opened a feed (`inlineTap` with `action` = `feed`, or `host` when your app opens the feed itself) divided by `inlineImpression`, grouped by `content_id`.

<Note>
  Inline surface events are sent by the iOS, Android and React Native SDKs from the release after 0.2.99 and by the Web SDK from 0.6.0. The Flutter SDK does not report them yet.
</Note>

### View lifecycle

| Type | Description | Key `event_data` fields |
|------|-------------|-------------------|
| `viewEnd` | User finished viewing a content item | Full playback summary (see below) |

The `viewEnd` event carries the richest payload — a complete summary of the viewing session including watch time, completion status, loop count, rebuffer stats, seek behavior, and device info. The server uses `viewEnd` events to populate the **video views** table that powers the metrics system.

### Ad lifecycle

| Type | Description | Key `event_data` fields |
|------|-------------|-------------------|
| `adRequest` | Ad was requested from the ad server | `adUnitId` |
| `adImpression` | Ad creative rendered | `adUnitId`, `adFormat` |
| `adStart` | Ad playback began | `adUnitId` |
| `adProgress` | Ad playback progress checkpoint | `adUnitId`, `percentComplete` |
| `adComplete` | Ad played to completion | `adUnitId` |
| `adSkip` | User skipped the ad | `adUnitId`, `skipTimeSeconds` |

<Note>
  Event types are not restricted to this list. The SDK may send custom event types, and they are stored and queryable like any other event.
</Note>
