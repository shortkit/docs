The player, widget and tile group components let you embed short-form video outside the full-screen feed. Use the **player** for a single video (hero sections, product pages, inline previews), the **widget** for a horizontal carousel or vertical grid of video cards (home screens, dashboards, discovery surfaces), and a **tile group** when you own the layout and want the SDK to own playback (story rings, bespoke grids, tiles mixed into your own collection views).

The player and widget require content fetched via `fetchContent()`. A tile group can be host-seeded the same way, or [fetch its own content per tile](#per-tile-feeds).

<Info>
  **Flutter:** Single player and widget components are coming soon for the Flutter SDK. For now, use the full-screen feed via [`ShortKitFeed`](/sdk/feed).
</Info>

## Fetching content

Before displaying videos, fetch `ContentItem` objects from the ShortKit API:

<Tabs>
  <Tab title="iOS (Swift)">
    ```swift
    // Fetch up to 5 items
    let items = try await shortKit.fetchContent(limit: 5)

    // Fetch with a filter (FeedFilter also accepts section, author, contentType, metadata)
    let filtered = try await shortKit.fetchContent(limit: 5, filter: FeedFilter(tags: ["sports"]))
    ```
  </Tab>
  <Tab title="Android">
    ```kotlin
    val items = shortKit.fetchContent(limit = 5) // suspend fun
    ```
  </Tab>
  <Tab title="React Native">
    ```tsx
    const { fetchContent } = useShortKit();
    const items = await fetchContent(5);
    ```
  </Tab>
  <Tab title="Web">
    ```js
    const items = await sk.fetchContent({ limit: 5 });
    ```
  </Tab>
</Tabs>

`fetchContent(limit:filter:)` returns an array of resolved `ContentItem` objects with streaming URLs, metadata, and captions. `limit` defaults to `10`. Pass a `FeedFilter` to restrict results by tags, section, author, content type, or custom metadata. For full model definitions see the [Content Types](/guides/content-types) guide.

## Single player

### PlayerConfig

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `cornerRadius` | `CGFloat` / `Float` / `number` | `12` | Corner radius of the player view in points. |
| `clickAction` | `PlayerClickAction` | `.feed` / `FEED` / `'feed'` | What happens when the user taps the player. See [click actions](#click-actions). |
| `autoplay` | `Bool` / `Boolean` / `boolean` | `true` | Start playback automatically when a content item is set. |
| `loop` | `Bool` / `Boolean` / `boolean` | `true` | Restart playback from the beginning when the video ends. |
| `muteOnStart` | `Bool` / `Boolean` / `boolean` | `true` | Begin playback muted. |
| `videoOverlay` | `VideoOverlayMode` / `OverlayConfig` | `.none` / `'none'` | Overlay rendered on top of the video. On React Native the property is named `overlay`. |

### Embedding a player

<Tabs>
  <Tab title="iOS (UIKit)">

            super.viewDidLoad()

            shortKit = ShortKit(
                apiKey: "pk_live_your_publishable_key",
                config: FeedConfig()
            )

                cornerRadius: 16,
                clickAction: .feed,
                muteOnStart: true

            playerVC = ShortKitPlayerViewController(shortKit: shortKit, config: config)

            playerVC.view.frame = CGRect(x: 16, y: 100, width: 200, height: 350)

                    playerVC.configure(with: first)
                    playerVC.activate()
                }
            }
        }

        }

### Activate and deactivate

The player does not manage its own visibility lifecycle. Call `activate()` when the player is on screen and `deactivate()` when it leaves. This gives you full control over playback in scroll views, tab bars, and navigation stacks.

| Method | Effect |
| --- | --- |
| `activate()` | Starts or resumes playback (respects `autoplay` and `muteOnStart`). |
| `deactivate()` | Pauses playback and releases the active player resources. |

On React Native, use the `active` prop instead of method calls. It defaults to the value of `config.autoplay` (which is `true` by default). Set it to `false` to pause and `true` to resume.

```tsx
<ShortKitPlayer
  contentItem={item}
  active={isVisible}
  config={{ clickAction: 'mute' }}
  style={{ width: 200, height: 350 }}
/>
```

## Widget

The widget displays a horizontal carousel or vertical grid of video cards with muted autoplay. Tapping a card opens the feed by default.

### WidgetConfig

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `cardCount` | integer | `3` | Number of video cards visible in the carousel. Has no effect when `layout` is `.grid`. |
| `cardSpacing` | float | `8` | Spacing between cards (carousel) or between grid cells, in points (iOS) or dp (Android/RN). |
| `cornerRadius` | float | `12` | Corner radius applied to each card. |
| `autoplay` | boolean | `true` | Whether the visible card plays automatically. |
| `muteOnStart` | boolean | `true` | Whether playback starts muted. |
| `loop` | boolean | `true` | Whether each card loops when it reaches the end. |
| `rotationInterval` | number | `10` | **Android and React Native only.** Time in milliseconds before the carousel advances to the next card (e.g. `10_000` for 10 seconds). On iOS, advancement is driven by the preview reaching its end — this property is ignored. Flutter support is coming soon. Applies to carousel layout only. |
| `clickAction` | enum | `.feed` | Action performed when a card is tapped. See [click actions](#click-actions). |
| `cardOverlay` / `overlay` | enum | `.none` | Overlay rendered on top of each card. The React Native prop is named `overlay`; iOS and Android use `cardOverlay`. |
| `layout` | `WidgetLayout` | `.carousel` | Layout mode — horizontal carousel or vertical grid. See [Layout](#layout). |
| `playbackMode` | `WidgetPlaybackMode` | `.singleVisibleRotating` | How the widget activates preview playback across cells. See [Playback mode](#playback-mode). |
| `previewDuration` | `TimeInterval` | `5` | Duration in seconds of the looping preview clip shown on each card. |
| `filter` | `FeedFilter?` | `nil` | Filter applied when the widget fetches content automatically. Same format as the `filter` parameter in `fetchContent()`. |

### Layout

`WidgetConfig.layout` controls whether the widget renders as a horizontal carousel or a vertical grid.

| Value | Description |
|---|---|
| `.carousel` | Default. Cards scroll horizontally in a single row within the widget's fixed height. |
| `.grid(columns:cellAspectRatio:scrollable:)` | Vertical grid with configurable columns. |

**Grid parameters:**

| Parameter | Type | Description |
|---|---|---|
| `columns` | `Int` | Number of columns. Must be at least `1`. |
| `cellAspectRatio` | `CGFloat` | Cell height ÷ cell width. Use `16.0/9.0` for portrait video, `9.0/16.0` for landscape, or `1.0` for square. |
| `scrollable` | `Bool` | When `true` (default) the grid manages its own scroll view and fills its assigned frame — use this for a standalone grid surface. When `false`, the grid expands to fit all of its content without internal scrolling and defers scrolling to the enclosing scroll view — use this to embed the grid inside a host-managed scroll view alongside other content. |

Two helper methods on `WidgetConfig` make it easier to size the container when using a non-scrollable embedded grid:

<Tabs>
  <Tab title="iOS (Swift)">
    ```swift
    // Height of each individual cell given the container's current width
    let cellHeight = config.gridCellHeight(forContainerWidth: view.bounds.width)

    // Total height needed to display all items (non-scrollable grids only)
    let totalHeight = config.preferredGridHeight(forContainerWidth: view.bounds.width, itemCount: items.count)
    ```

    `gridCellHeight` returns `nil` for carousel layouts. `preferredGridHeight` returns `nil` for carousel layouts and for scrollable grid layouts (where total height is unbounded).

### Playback mode

`WidgetConfig.playbackMode` controls how the widget activates preview playback across its cells.

| Value | Works with | Description |
|---|---|---|
| `.singleVisibleRotating` | Carousel | Default. One visible card plays at a time. When its preview ends the widget advances to the next visible card. Off-screen cards never play. |
| `.allVisibleSimultaneous` | Carousel | Up to 3 visible cards play simultaneously. Each card loops its own preview independently. Cards beyond the first 3 visible and all off-screen cards stay paused. |
| `.gridAlternating(startSide:)` | Grid | One cell per visible row plays at a time, alternating left and right columns on successive rows, up to 4 active previews simultaneously. Each active cell loops its preview. When more rows are equally visible, the topmost rows take priority. When using this mode with a non-scrollable embedded grid, call `parentScrollViewDidScroll(_:)` on every scroll event so the widget can correctly score cell visibility against the parent viewport. |

The `startSide` parameter on `gridAlternating` controls which column plays in the first row:

<Tabs>
  <Tab title="iOS (Swift)">
    ```swift
    // Row 0 → rightmost column, row 1 → leftmost, row 2 → rightmost, …
    let config = WidgetConfig(
        layout: .grid(columns: 3, cellAspectRatio: 16.0 / 9.0),
        playbackMode: .gridAlternating(startSide: .right)
    )
    ```

    `GridSide` values: `.left` (default), `.right`.

### WidgetInput

`WidgetInput` describes a video by its playback ID. Pass an array of these to `configure(with:)` or `appendItems(_:)`.

<Tabs>

### Embedded (non-scrollable) grid

When the grid sits inside a host-managed scroll view alongside other content — for example, a home screen with a carousel above and a grid below — set `scrollable: false`. The grid expands to fit all of its content and lets the parent scroll view handle scrolling.

Three additional steps are required:

1. **Resize the container as items load.** Subscribe to `onContentHeightChange` and update your height constraint whenever the grid's content height changes.
2. **Forward scroll events.** Call `parentScrollViewDidScroll(_:)` from the parent scroll view delegate so the widget can correctly score which grid cells are visible.
3. **Append items for pagination.** Call `appendItems(_:)` to load additional items without a full reload.

<Tabs>
  <Tab title="iOS (UIKit)">
    ```swift ViewController.swift
    import ShortKitSDK

    class HomeViewController: UIViewController, UIScrollViewDelegate {
    private var shortKit: ShortKit!
    private var widgetVC: ShortKitWidgetViewController!
    private var gridHeightConstraint: NSLayoutConstraint!

    private let scrollView: UIScrollView = {
        let sv = UIScrollView()
        sv.translatesAutoresizingMaskIntoConstraints = false
        return sv
    }()

    override func viewDidLoad() {
        super.viewDidLoad()

        // Set up the host scroll view
        view.addSubview(scrollView)
        scrollView.delegate = self
        NSLayoutConstraint.activate([
            scrollView.topAnchor.constraint(equalTo: view.topAnchor),
            scrollView.leadingAnchor.constraint(equalTo: view.leadingAnchor),
            scrollView.trailingAnchor.constraint(equalTo: view.trailingAnchor),
            scrollView.bottomAnchor.constraint(equalTo: view.bottomAnchor),
        ])

        shortKit = ShortKit(
            apiKey: "pk_live_your_publishable_key",
            config: FeedConfig()
        )

        let config = WidgetConfig(
            cornerRadius: 8,
            layout: .grid(columns: 3, cellAspectRatio: 16.0 / 9.0, scrollable: false),
            playbackMode: .gridAlternating()
        )

        widgetVC = ShortKitWidgetViewController(shortKit: shortKit, config: config)

        // Resize the container whenever content is added
        widgetVC.onContentHeightChange = { [weak self] height in
            self?.gridHeightConstraint.constant = height
        }

        addChild(widgetVC)
        widgetVC.view.translatesAutoresizingMaskIntoConstraints = false
        scrollView.addSubview(widgetVC.view)
        gridHeightConstraint = widgetVC.view.heightAnchor.constraint(equalToConstant: 0)
        NSLayoutConstraint.activate([
            widgetVC.view.topAnchor.constraint(equalTo: scrollView.contentLayoutGuide.topAnchor),
            widgetVC.view.leadingAnchor.constraint(equalTo: scrollView.contentLayoutGuide.leadingAnchor),
            widgetVC.view.trailingAnchor.constraint(equalTo: scrollView.contentLayoutGuide.trailingAnchor),
            widgetVC.view.bottomAnchor.constraint(equalTo: scrollView.contentLayoutGuide.bottomAnchor),
            widgetVC.view.widthAnchor.constraint(equalTo: scrollView.frameLayoutGuide.widthAnchor),
            gridHeightConstraint,
        ])
        widgetVC.didMove(toParent: self)

        Task {
            let items = try await shortKit.fetchContent(limit: 10)
            let inputs = items.compactMap { $0.playbackId.map { WidgetInput.video(playbackId: $0) } }
            widgetVC.configure(with: inputs)
        }
    }

    // Forward scroll events so the grid can score cell visibility
    func scrollViewDidScroll(_ scrollView: UIScrollView) {
        widgetVC.parentScrollViewDidScroll(scrollView)
    }

    itemCount: items.count
) ?? 0
gridHeightConstraint.constant = initialHeight
```

#### Appending items

Call `appendItems(_:)` to add more items to the grid without a full reload — for example, when the user scrolls near the bottom:

```swift
Task {
    let nextPage = try await shortKit.fetchContent(limit: 10, filter: FeedFilter(tags: ["sports"]))
    let inputs = nextPage.compactMap { $0.playbackId.map { WidgetInput.video(playbackId: $0) } }
    widgetVC.appendItems(inputs)
}
```

`appendItems` is a no-op on an empty input array. It works on both scrollable and non-scrollable grid layouts, inserting items incrementally without a full reload. On carousel layouts it triggers a full reload instead.

### Auto-rotation

<Note>
  Auto-rotation applies to carousel layout only (`WidgetLayout.carousel`). Grid layouts use the `playbackMode` setting to control preview activation instead.
</Note>

When `autoplay` is `true` (the default), the carousel widget automatically advances through cards. How advancement is triggered differs by platform:

- **iOS** — advancement is driven by the preview reaching its end (`singleVisibleRotating` mode). Each card plays until its preview clip finishes, then the carousel moves to the next card. `rotationInterval` has no effect on iOS.
- **Android and React Native** — advancement is timer-based: the carousel advances to the next card after `rotationInterval` elapses, regardless of playback position.

On all platforms, when the carousel reaches the last card it wraps back to the first. Rotation pauses while the user is actively swiping and resumes once the gesture ends.

<Warning>
  The `rotationInterval` unit differs across platforms. Android and React Native expect milliseconds (e.g. `10_000` / `10000`). The property is ignored on iOS.
</Warning>

## Tile groups

A tile group is the widget without the layout. You place tiles wherever you like — a horizontal stack of story rings, cells in your own list or collection view, a bespoke grid — and the group owns everything media-related: which tile previews (visibility scan plus the same preview-driven rotation as the widget), player leasing, poster prefetch around the visible window, and tap → full-screen feed with the widget's zoom-from-tile transition.

<Info>
  Tile groups are available on **iOS**, **Android**, **React Native** and **Web** (SDK 0.6.0+). Per-tile feeds (below) are iOS-only for now.
</Info>

### TileGroupConfig

Every field has the same meaning as its `WidgetConfig` counterpart. There are no layout fields, because you own the layout.

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `playbackMode` | `TilePlaybackMode` | `.singleVisibleRotating` | `.singleVisibleRotating` (one visible tile previews, advancing when its preview ends), `.allVisibleSimultaneous` (every sufficiently visible tile previews, capped), `.gridAlternating` (one tile per row previews, alternating columns — see [Grid-alternating playback](#grid-alternating-playback)) or `.none` (posters only; taps still open the feed). |
| `previewDuration` | `TimeInterval?` | `nil` | Length of each tile's preview clip in seconds. `nil` lets the server choose per clip (5 s fallback). |
| `autoplay` | boolean | `true` | Whether a visible tile previews automatically. |
| `autoplayDelay` | `TimeInterval` | `0` | How long a tile lingers on its poster after being chosen before playback starts. |
| `muteOnStart` | boolean | `true` | Whether previews start muted. |
| `loop` | boolean | `true` | Whether a preview loops when it reaches the end. |
| `clickAction` | enum | `.feed` | Action performed when a tile is tapped. See [click actions](#click-actions). |
| `feedConfig` | `FeedConfig` | `FeedConfig()` | Config for the full-screen feed opened on tap. With [per-tile feeds](#per-tile-feeds) each tile carries its own instead. |
| `feedMask` | `FeedMaskMode` | `.none` | Optional host chrome wrapped around the opened feed. |
| `prefetchAhead` / `prefetchBehind` | integer | `4` / `1` | Poster-prefetch horizon, in items, ahead of and behind the visible window. |

<Note>
  **Web:** enum values are strings (`playbackMode: 'singleVisibleRotating'`, `clickAction: 'feed'`), times are in seconds, and the prefetch horizon is one field, `prefetch: { ahead: 4, behind: 1 }`. Web also accepts `filter`, the filter for the feed opened on tap when `feedConfig` sets none, and `presentation`, the placement of that feed.
</Note>

### Grid-alternating playback

<Note>
  Available on **iOS**, **Android**, **React Native** and **Web**.
</Note>

`.gridAlternating` previews one tile per visible row, alternating between the leftmost and rightmost columns on successive rows, capped at 4 simultaneous previews. Middle columns never preview. Use it when you lay tiles out in a grid and want the same staggered preview pattern as the [widget's grid](#playback-mode) while owning the layout yourself. You pass nothing per tile.

The group reads rows and outer columns from the tiles' on-screen frames on every visibility scan. Tiles whose vertical centers line up form a row. The outer columns are the left and right edges shared by the tiles that sit fully inside the viewport, so a short last row never promotes its middle tile to a column.

Each row keeps its side while it stays on screen, so scrolling never flips which tiles preview. When more rows are equally visible, the top rows take priority within the 4-tile cap. A tile-width change (rotation, resize) resets the alternation to `startSide`.

`startSide` selects which column previews in the first row. It is optional and defaults to the leftmost column.

<Tabs>
  <Tab title="iOS (Swift)">
    ```swift
    // startSide is optional; .left is the default.
    let config = TileGroupConfig(playbackMode: .gridAlternating(startSide: .right))
    ```

    `GridSide` values: `.left` (default), `.right`. Write the case with parentheses — `.gridAlternating()` — the same as `WidgetPlaybackMode`.
  </Tab>
  <Tab title="Android">
    ```kotlin
    // gridStartSide is optional; GridSide.LEFT is the default.
    val config = TileGroupConfig(
        playbackMode = TilePlaybackMode.GRID_ALTERNATING,
        gridStartSide = GridSide.RIGHT,
    )
    ```
  </Tab>
  <Tab title="React Native">
    ```tsx
    // Pass the mode in the tile group config. startSide is optional; 'left' is the default.
    config={{ playbackMode: { type: 'gridAlternating', startSide: 'right' } }}
    ```
  </Tab>
  <Tab title="Web">
    ```js
    const group = sk.createTileGroup({
      config: { playbackMode: { type: 'gridAlternating', startSide: 'right' } },
      content,
    });
    ```

    `startSide` values: `'left'` (default), `'right'`.
  </Tab>
</Tabs>

### Embedding tiles

Create one group per surface, hand each tile to it, and tell the group which item the tile renders. The group reads each tile's frame to decide what previews; it never moves or sizes a tile.

<Tabs>
  <Tab title="iOS (Swift)">
    ```swift
    let group = ShortKitTileGroup(shortKit: shortKit, config: TileGroupConfig())

    // Host-seeded: fetch, then give the group its ordered item list.
    let items = try await shortKit.fetchContent(limit: 10, filter: FeedFilter(tags: ["sports"]))
    group.setItems(items.compactMap { item in
        item.playbackId.map { WidgetInput.video(playbackId: $0, contentId: item.id, thumbnailUrl: item.thumbnailUrl) }
    })

    // Lay the tiles out however you like; each one is keyed by playback ID.
    for item in items {
        let tile = ShortKitTileView(group: group)
        tile.itemId = item.playbackId
        tile.cornerRadius = 12
        stack.addArrangedSubview(tile)
    }

    // Gate the surface like a widget: `false` releases every player.
    group.setActive(false)   // leaving the screen
    group.setActive(true)    // back on screen

    // Required teardown.
    group.release()
    ```

    A tile that outlives its group falls back to its poster.
  </Tab>
  <Tab title="Web">
    ```js tiles.js
    const sk = new ShortKit({ apiKey: 'pk_live_your_publishable_key' });

    // Self-fetching: a content controller fetches pages for the group, and the
    // feed opened from a tile continues from where the tiles left off.
    const content = sk.createContentController({ source: 'algorithmic', limit: 10, filter: { tags: ['sports'] } });
    const group = sk.createTileGroup({ config: { playbackMode: 'singleVisibleRotating' }, content });

    // Host-seeded instead: pass `items` (from `sk.fetchContent()`) rather than `content`,
    // or call `group.setItems(items)`, and create one tile per item yourself.

    // Lay the tiles out however you like; each one is keyed by playback ID.
    const row = document.getElementById('stories');
    const tiles = new Map();
    content.observe(({ items }) => {
      for (const item of items) {
        if (!item.playbackId || tiles.has(item.id)) continue;
        const el = document.createElement('div');
        el.className = 'story';
        row.appendChild(el);
        tiles.set(item.id, group.attachTile(el, { itemId: item.playbackId, cornerRadius: 12 }));
      }
    });

    // Gate the surface: `false` releases every player.
    group.setActive(false);   // leaving the screen
    group.setActive(true);    // back on screen

    // Required teardown.
    group.release();
    content.dispose();
    ```

    ```css
    /* You size the tiles; the group never does. */
    #stories { display: flex; gap: 8px; overflow-x: auto; }
    .story { flex: 0 0 96px; aspect-ratio: 9 / 16; }
    ```
  </Tab>
</Tabs>

Keep one autoplaying group per screen: several groups on one screen compete for the same player pool, so gate all but one with `setActive(false)`.

### Ready for display

<Note>
  **Web only** (SDK 0.6.0+). iOS, Android and React Native parity is planned.
</Note>

Each tile reports when its media is on screen: its poster (or first frame) has loaded, or its preview has started. Use it to show a placeholder in each cell until there is something to show, and to hold back chrome you draw over the tile.

It fires once each time the tile is bound to an item. When a tile is given a different item, it resets and fires again once that item's media shows. If a tile's poster fails to load, it reports ready only once its preview starts; a tile whose poster fails and that never previews stays on its placeholder.

<Tabs>
  <Tab title="iOS (Swift)">
    Not yet supported on iOS.
  </Tab>
  <Tab title="Android">
    Not yet supported on Android.
  </Tab>
  <Tab title="React Native">
    Not yet supported on React Native.
  </Tab>
  <Tab title="Web">
    Pass `onReadyForDisplay` to `attachTile`. Keep the placeholder as the first child of the tile element, so the media fades in over it:

    ```js
    const el = document.createElement('div');
    el.className = 'story is-loading';
    el.innerHTML = '<div class="placeholder"></div>';
    const tile = group.attachTile(el, {
      itemId: item.playbackId,
      onReadyForDisplay: () => el.classList.remove('is-loading'),
    });

    tile.isReadyForDisplay; // the current state
    ```

    ```css
    .story .placeholder { position: absolute; inset: 0; background: #e9e5de; }
    .story > :not(.placeholder) { transition: opacity 180ms ease-out; }
    .story.is-loading > :not(.placeholder) { opacity: 0; }
    ```

    If you give a tile a different item (`tile.setItemId(...)`), add `is-loading` back first so the new item fades in too. Setting `tile.onReadyForDisplay` after the tile is already ready does not call it; read `tile.isReadyForDisplay` instead.

    To watch every tile from one place, listen on the group:

    ```js
    group.on('tileReadyForDisplay', ({ itemId, tile }) => {
      tile.element.classList.remove('is-loading');
    });
    ```

    In React, pass `onReadyForDisplay` to `<ShortKitTile>`. Its children render **above** the media, so keep the placeholder there and remove it in the callback rather than fading the media in under it.
  </Tab>
</Tabs>

### Per-tile feeds

<Note>
  **iOS only** (SDK 0.3.1+). Android, React Native and Web parity is planned.
</Note>

By default every tile in a group opens the *same* feed — `config.feedConfig` — at the tapped item's position, exactly like widget cards. A row of story rings needs the opposite: each ring is an entry point into a **different** feed. "Trending" opens the unfiltered feed, "Baseball" opens `FeedFilter(tags: ["baseball"])`, "Hockey" opens `tags: ["hockey"]`, each starting on the clip the ring was showing.

Build the group from a list of `TileFeed`s instead of seeding items, and the group fetches the first page of each feed itself. Each tile's preview is its feed's first clip, and tapping it opens that feed with the filter already applied, the tapped clip still playing, the rest of the page queued behind it, and pagination continuing on the server with the same filter. Nothing reloads, and every item carries its full metadata.

```swift
struct TileFeed {
    var id: String            // your key for the tile ("baseball")
    var feedConfig: FeedConfig // the feed this tile previews and opens — filter, overlays, presentation
    var limit: Int = 10        // page size of the one fetch behind the tile
}
```

```swift
let base = FeedConfig(videoOverlay: .custom { ShopOverlayView() }, feedSource: .algorithmic)
func feed(filter: FeedFilter?) -> FeedConfig { var c = base; c.filter = filter; return c }

let group = ShortKitTileGroup(
    shortKit: shortKit,
    config: TileGroupConfig(playbackMode: .singleVisibleRotating, clickAction: .feed),
    tileFeeds: [
        TileFeed(id: "trending", feedConfig: feed(filter: nil)),
        TileFeed(id: "baseball", feedConfig: feed(filter: FeedFilter(tags: ["baseball"]))),
        TileFeed(id: "hockey",   feedConfig: feed(filter: FeedFilter(tags: ["hockey"]))),
    ])

// Tiles are keyed by the feed id, not a playback ID — you lay them out before anything is fetched.
for story in ["trending", "baseball", "hockey"] {
    let ring = ShortKitTileView(group: group)
    ring.tileFeedId = story
    ring.cornerRadius = 39   // a 78pt circle
    row.addArrangedSubview(ring)
}

// Which tiles resolved to a clip. Ids missing from the map got nothing
// (empty feed or failed fetch) — hide those tiles.
group.onTilesLoaded = { resolved in
    hideRings(except: Set(resolved.keys))
}

// Which tile opened the feed, so you can set chrome for it (a sport picker, a title).
group.onTileFeedOpened = { feedVC, tileId in
    sportPicker.attach(to: feedVC, preselected: tileId == "trending" ? nil : tileId)
}
```

The group gives each tile a clip no earlier tile already shows, so the same item never appears in two rings even when an unfiltered feed overlaps a filtered one. A feed whose page is exhausted by that rule yields no tile and is omitted from `onTilesLoaded`.

On a self-fetching group, `setItems`, `setFeedItems` and `bindContent` are no-ops; the group owns its items.

#### Preview progress

Two callbacks report what the group is doing, so you can draw a progress ring or highlight the active tile without running your own timer:

```swift
// The tile that is previewing (its id), or nil when none is — rotated away,
// scrolled out, deactivated, or a feed is open. A hand-off is nil, then the next id.
group.onAutoplayTileChanged = { tileId in
    rings.forEach { $0.isActive = ($0.id == tileId) }
}

// The previewing tile's clock, the same `PlayerTime` the feed's `ShortKitPlayer.time`
// publishes (~2 Hz). `duration` is the preview's length, so `current / duration` is progress.
group.onAutoplayTileTime = { tileId, time in
    rings[tileId]?.progress = time.current / time.duration
}

// Or subscribe directly, exactly as a feed overlay does.
group.autoplayPlayer(for: "baseball")?.time.sink { time in … }
```

`onTileFeedOpened`, `onAutoplayTileChanged` and `onAutoplayTileTime` also fire on host-seeded groups, carrying the playback ID instead of a feed id. They are distinct from `onPreviewTileChanged`, which reports hold-to-preview pins, not rotation.

## Click actions

`PlayerConfig.clickAction`, `WidgetConfig.clickAction` and `TileGroupConfig.clickAction` accept the same values:

| Value | Behavior |
| --- | --- |
| `.feed` / `PlayerClickAction.FEED` / `'feed'` | Opens the full-screen feed starting at the tapped item. This is the default. On a tile group built with [per-tile feeds](#per-tile-feeds), opens that tile's own feed. |
| `.mute` / `PlayerClickAction.MUTE` / `'mute'` | Toggles audio mute. |
| `.none` / `PlayerClickAction.NONE` / `'none'` | No action. Useful when you handle taps yourself. |
